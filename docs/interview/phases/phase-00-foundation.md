## Beginner

### B1. What is a Gradle convention plugin and why does this repo have one?

**A strong answer contains**
- A plugin whose id is its file name; a module applies `id("streampulse.java-conventions")` and *opts in*.
- It centralises the toolchain, tests, JaCoCo, Spotless and compiler flags in one place, so twelve
  modules do not repeat them.
- The opposite of pushing configuration down from the root.

**Open** `build-logic/src/main/kotlin/streampulse.java-conventions.gradle.kts`

### B2. What does the version catalog do?

**A strong answer contains**
- One file holds every version, and type-safe accessors such as `libs.assertj` give autocomplete.
- Bundles group libraries; BOMs align families (JUnit, AWS, gRPC). No literal version strings in module
  build files.
- Stable releases only: no milestones, release candidates or snapshots.

**Open** `gradle/libs.versions.toml`

### B3. Why `TenantId` instead of a `String`?

**A strong answer contains**
- A swapped `(tenantId, titleId)` argument becomes a compile error instead of a cross-tenant leak.
- It validates once at the boundary and normalises (trim, lower-case with `Locale.ROOT`), and rejects
  anything that fails the allowed pattern, so every layer can trust it.
- The value ends up in Kafka keys, Redis prefixes and metric labels, so its shape matters.

**Open** `libs/platform/src/main/java/com/streampulse/platform/domain/TenantId.java`

### B4. Why is the event id generated by the client?

**A strong answer contains**
- A retry carries the same id, so a de-duplication check turns at-least-once into effectively-once.
- A UUID can be generated offline with no coordination. The same idea as an idempotency key on a
  payment API.
- `EventId.random()` is for tests and the load generator only, never the ingest path.

**Open** `libs/platform/src/main/java/com/streampulse/platform/domain/EventId.java`

### B5. What are `test` and `integrationTest`, and why split them?

**A strong answer contains**
- `test` excludes classes ending in `IT` and needs no Docker; `integrationTest` runs only those and starts
  containers. `check` depends on both.
- They share one source set and are split by file name, not by directory.

**Open** `build-logic/src/main/kotlin/streampulse.java-conventions.gradle.kts`

### B6. What does `make check` do, and why is there a Makefile at all?

**A strong answer contains**
- It runs the format check and the full build (compile, tests, ArchUnit).
- Not everything is a Gradle task: Docker, Terraform and demo scripts are not, so one entry point beats a
  README of commands people copy wrong. `make help` lists everything.

**Open** `Makefile`

## Mid

### M1. Why a compact constructor in a record, and what can go wrong?

**A strong answer contains**
- It runs before field assignment, so it is where validation and normalisation go.
- Reassigning the parameter changes what is stored, so normalise *then* validate.
- Records are only shallowly immutable: a mutable component would still leak.
- Equality derives from the normalised component, so equal spellings give equal keys.

**Open** `libs/platform/src/main/java/com/streampulse/platform/domain/TenantId.java`

### M2. What is the catalog-accessor problem in a precompiled script plugin?

**A strong answer contains**
- Generated `libs.` accessors do not exist inside precompiled script plugins, because the plugin compiles
  before project accessors are generated.
- The popular workaround injects a generated class by reflection. The repo declined it and used the
  documented `VersionCatalogsExtension` with `findLibrary`, so a missing alias fails loudly at
  configuration time, naming the alias.
- Cost: more verbose. Gain: no hack to maintain.

**Open** `specs/00-foundation/design.md`

### M3. What does ArchUnit enforce here, and what are `allowEmptyShould` and the test-class exclusion for?

**A strong answer contains**
- Four platform rules: no field injection, the domain package imports no framework types, inbound
  adapters do not reach outbound ones, no `java.util.Date` or `Calendar`.
- `allowEmptyShould(true)` lets a rule pass before its packages exist. The danger: rename a package and
  the rule goes vacuously green, so it can never fail.

**Open** `libs/platform/src/test/java/com/streampulse/platform/ArchitectureRulesTest.java`

### M4. How do you prove a quality gate works?

**A strong answer contains**
- Violate it on purpose, watch it fail, revert. The Spotless gate failed in under a second on badly
  formatted code; ArchUnit named the offending class.
- A gate nobody has seen fail is not a gate.
- Honesty: those two demos ran against code that has since been removed, so rerun them before you cite
  them.

**Open** `MILESTONES.md` (Phase 0, "Quality gates — verified by breaking them")

### M5. Why does Testcontainers need a Docker socket, an API-version pin and a Ryuk override on macOS?

**A strong answer contains**
- Docker Desktop exposes several sockets and only some answer. The build picks the first that exists and
  sets the host, a pinned API version (the newer engine rejects the old default) and the in-engine socket
  path for Ryuk (the sidecar that reaps containers).
- It applies only when `DOCKER_HOST` is unset, so CI is unaffected.
- The story behind it is B1 in [what broke](../05-what-broke.md), story 4.

**Open** `build-logic/src/main/kotlin/streampulse.java-conventions.gradle.kts`

### M6. What does `failOnNoDiscoveredTests = false` do, and what is the risk?

**A strong answer contains**
- Gradle 9 fails a test task that finds no tests, and `libs:platform` and `libs:contracts` have no
  integration tests.
- Risk: a misspelt `IT` suffix silently skips tests. A mitigation would be a convention test asserting
  container-using tests match the naming pattern.

**Open** `build-logic/src/main/kotlin/streampulse.java-conventions.gradle.kts`

## Senior

### S1. Convention plugins versus `allprojects`: what is the real argument?

**A strong answer contains**
- `allprojects` couples every module to the root and answers "why does this module have that
  dependency?" badly; convention plugins let a module opt in, so a library module does not inherit
  Spring.
- Be careful with the configuration-cache claim. The repo says `allprojects` breaks it, but the root
  build has a task that reads all subprojects, and **I have not confirmed the configuration cache is on**
  (there is no `gradle.properties`). Say that rather than defend the claim blindly.
- A composite `build-logic` is cached separately; the repo says a `buildSrc` change invalidates the whole
  build cache (the repo's claim, unverified by me).

**Open** `build.gradle.kts`

### S2. Supply chain: what does the build protect, and what is missing?

**A strong answer contains**
- Protected: the wrapper checksum is pinned; repositories are declared once in settings, so a module
  cannot add its own. **Check the exact `RepositoriesMode` semantics in the Gradle docs**: I believe
  `PREFER_SETTINGS` ignores project repositories and that `FAIL_ON_PROJECT_REPOS` is the strict mode, but
  I have not verified it, and the repo's comment may overstate it.
- Missing: dependency locking, verification metadata for checksums and signatures, vulnerability scanning
  in CI. "Stable releases only" is human discipline; propose a build check that fails on a milestone or
  snapshot version.

**Open** `settings.gradle.kts`

### S3. What can ArchUnit not enforce?

**A strong answer contains**
- It reads bytecode on the module's own classpath, so the platform copy of the rules cannot see a service
  at all. That is why each service has its own rules test, and why a dropped module drops its rules
  silently.
- The domain rule is a finite denylist of package prefixes, not an allowlist.
- It cannot enforce runtime behaviour: `Clock` injection, transaction boundaries, idempotency semantics.
  The `Clock` rule is a convention; ArchUnit bans `Date` and `Calendar` but not `Instant.now()` (one
  service adds its own ban).

**Open** `services/control-plane/src/test/java/com/streampulse/controlplane/ControlPlaneArchitectureRulesTest.java`

### S4. Why a monorepo, and when would you split it?

**A strong answer contains**
- Coordination cost versus deployment independence. One author with tightly coupled contracts: atomic
  contract changes, one build proving everything compiles, no version skew.
- Honest negatives: the build slows as modules grow, and nothing physically stops reaching into another
  module (hence ArchUnit).
- Revisit if CI exceeds about ten minutes or release cadences genuinely diverge.

**Open** `docs/adr/0001-multi-module-single-repo.md`

### S5. Assess this CI pipeline.

**A strong answer contains**
- It runs the format check and the full build, which includes integration tests, then uploads reports.
- Missing: a coverage gate, protobuf lint, web build and tests, Terraform validation, Prometheus rule
  tests, an image build, dependency scanning. The integration-test reports are not uploaded.
- **No evidence it has run.** The notes say it was committed without a remote at first. Do not claim
  green CI without checking the Actions tab.
- Proposal: split fast and slow jobs, cache on the catalog, add path filters per module.

**Open** `.github/workflows/ci.yml`

### S6. Value objects as a security boundary: what do they cover and what not?

**A strong answer contains**
- Namespaced keys (`tenant#x:event#id`) prevent collisions across tenants; a validated type removes
  injection-shaped characters from keys.
- Not covered: authorisation, and where the tenant comes from (the token, in a later phase). Phase 0
  proves the type behaviour only, not Redis atomicity.

**Open** `libs/platform/src/main/java/com/streampulse/platform/domain/EventId.java`
